# AGENTS.md — Rules for AI Agents working on SAARTHI (SIH 26186)

**Project**: SAARTHI (working name; सारथी = the charioteer/guide) — AI-Based Predictive Personnel Stress & Welfare Monitoring System for Uniformed Forces.
**PS**: SIH 2026 · PS ID 26186 · CRPF / Ministry of Home Affairs · MedTech/HealthTech.

## Repo map

| Path | Purpose | Who owns it |
|---|---|---|
| `docs/` | **THE BRAIN.** All product knowledge. Every implementation decision traces here. | one named owner per file (see `docs/README.md`) |
| `executable/` | **THE HANDS.** Per-member plans, AI-agent execution prompts, checklists, board. | `kv` (PM) owns structure; members own their own folder |
| `docs/architecture/decisions/` | Architecture Decision Records (MADR). Add new ones; never delete. | kv |
| `docs/features/` | One comprehensive doc per feature (F01–F09) | see per-file header |

## Non-negotiable rules

1. **`docs/` is the source of truth.** Before writing any code for a task, read the feature doc it maps to (`docs/features/F*.md`). After finishing a task, update the affected docs **in the same PR**.
2. **One owner per file.** Never edit a file owned by someone else. Ownership is stamped in each doc's header.
3. **`executable/board.md` is the single status source.** Task owners may edit ONLY the `Status` column of their own rows. Only `kv` (PM) adds/removes/reassigns tasks. `executable/<member>/checklist.md` files are GENERATED by `executable/tools/sync-checklists.py` — never hand-edit them.
4. **Task IDs everywhere.** Every PR title starts with its task ID: `[BACK-003] HR signal ingestion endpoint`. Every commit on a task references the ID.
5. **Branch → notify → merge.** Everyone works only on their own branch (branch name = your name), never directly on `main`. When a task and its testing are done: push, open a PR into `main`, and **notify `kv` (maintainer)**. **Only `kv` merges PRs into `main`** (kv's own PRs are reviewed by neel). Never merge your own PR.
6. **Diátaxis routing.** Docs live in one of four quadrants: `product/` (why), `architecture/` + `features/` (how), `quality/` + `guides` (how-to), `explanation/` (why-it-works). Never mix a how-to into an explanation page.
7. **No invented statistics.** Impact claims are Low/Med/High or reasoned estimates with a cited source. This is a judged SIH red flag.
8. **English + Hindi awareness.** All user-facing strings referenced in docs must list the i18n keys used.
9. **Welfare, not discipline.** No code path may expose an individual risk score to command hierarchy. This is an architectural firewall (ADR-0003) — if a change violates it, reject the change.
10. **Task sizing.** kv + neel carry the backbone. ayush, manan, risa, tejas are 1st-years: their tasks are deliberately simple (verify, collect, copy, record, practice). If a task feels too big, split it with kv — that is expected.

## Workflow for an AI agent on this repo

```
1. Read this file (AGENTS.md)
2. Read executable/<your-member>/plan-for-<name>.md      → your role + tasks
3. Read executable/<your-member>/execute.md              → your execution prompt
4. Read executable/<your-member>/checklist.md            → generated task list with dates
5. Read docs/README.md → the feature doc for each task    → the "brain" for your work
6. Work on your own git branch (branch name = your name)
7. PR title starts with task ID · docs updated in same PR · **notify kv · only kv merges to main**
8. Run: python3 executable/tools/sync-checklists.py       (kv runs this daily)
```

## Commands (conventions — verify against package.json before running)

- JS/TS tooling: **bun** (`bun install`, `bun run dev`, `bun test`)
- Backend: Python 3.11+, FastAPI (`uvicorn app.main:app --reload`), PostgreSQL
- Mobile: Expo / React Native (`bun run ios` / `bun run android`), offline-first SQLite
- Docs check: `python3 executable/tools/sync-checklists.py --check`

## Escalation

Blocked > 24h → set Status `[!]` on your board row with reason + who unblocks, and ping `kv`. Do not silently work around another member's deliverable.
